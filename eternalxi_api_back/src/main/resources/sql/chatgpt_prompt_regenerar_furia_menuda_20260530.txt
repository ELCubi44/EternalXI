PARTE 1 — QUÉ FALLÓ LA VEZ ANTERIOR (NO LO REPITAS)
================================================================================

El script anterior insertó jugadores y supertécnicas en catálogo, pero dejó
**0 enlaces** en jugador_supertecnica porque usaste **nombres de columna
incorrectos** al hacer SELECT de IDs. MySQL devolvió ERROR en esos SELECT y
las variables @st1..@st4 quedaron NULL; los INSERT en jugador_supertecnica
no crearon filas (o fallaron en silencio con INSERT IGNORE).

ERRORES CONCRETOS QUE COMETISTE (PROHIBIDO volver a usarlos):

  INCORRECTO                              CORRECTO
  ─────────────────────────────────────   ─────────────────────────────────
  j.id_jugador                            j.id
  SELECT id_jugador FROM jugadores        SELECT id FROM jugadores
  id_supertecnica (como columna en ST)    st.id  o  id
  SELECT id_supertecnica FROM supertecnicas   SELECT id FROM supertecnicas
  e.id_equipo (en tabla equipos)          e.id
  JOIN equipos e ON e.id_equipo = ...     JOIN equipos e ON e.id = j.id_equipo
  et.id_equipo como PK de equipos         equipos.id es la PK; id_equipo solo
                                          existe en tablas hijas (equipo_traduccion,
                                          jugadores.id_equipo)

REGLA DE ORO: En MySQL la primary key de temporadas, equipos y jugadores se
llama **`id`**. En supertecnicas también es **`id`** (BIGINT).
Las FKs hacia esas tablas se llaman id_temporada, id_equipo, id_jugador,
id_supertecnica — pero **nunca** uses id_jugador ni id_supertecnica como
nombre de columna al hacer SELECT sobre la tabla padre.

Patrón OBLIGATORIO para obtener ID de supertécnica:

  SELECT id INTO @st1
  FROM supertecnicas
  WHERE nombre = 'campana_temeraria'
    AND potencia = 80
    AND tipo = 'PARADA'
    AND estilo = 'VALIENTE'
  LIMIT 1;

  -- La columna es `id`. NUNCA escribas: SELECT id_supertecnica INTO ...

Patrón OBLIGATORIO tras insertar jugador:

  SET @id_jugador = LAST_INSERT_ID();
  -- @id_jugador contiene jugadores.id, NO hay columna id_jugador en jugadores

Patrón OBLIGATORIO para enlazar ST al jugador:

  INSERT INTO jugador_supertecnica (id_jugador, id_supertecnica, orden)
  VALUES (@id_jugador, @st1, 1);

  -- id_jugador e id_supertecnica SÍ son columnas de jugador_supertecnica (FK).
  -- Los valores vienen de @id_jugador y @st1..@st4 obtenidos con SELECT id ...

SOBRE WARNINGS: INSERT IGNORE con "Duplicate entry" (1062) es normal si
re-ejecutas el script. Lo grave es **0 rows affected** en jugador_supertecnica
porque @stN era NULL.

PARTE 2 — ESQUEMA REAL DE TABLAS (MySQL 8, BD EternalXI)
================================================================================

--- temporadas ---
  id              INT AUTO_INCREMENT PK
  nombre          VARCHAR   (fallback español, ej. 'Eterno Campeon')
  foto            VARCHAR NULL

--- temporada_traduccion ---
  id_temporada    INT FK → temporadas.id
  locale          VARCHAR(5)   'es' | 'en'
  nombre          VARCHAR(100)
  PK (id_temporada, locale)

--- equipos ---
  id              INT AUTO_INCREMENT PK
  nombre          VARCHAR   (fallback español)
  id_temporada    INT FK → temporadas.id
  foto            VARCHAR NULL

--- equipo_traduccion ---
  id_equipo       INT FK → equipos.id
  locale          VARCHAR(5)
  nombre          VARCHAR(120)
  PK (id_equipo, locale)

--- jugadores ---
  id              INT AUTO_INCREMENT PK
  id_equipo       INT FK → equipos.id
  nombre          VARCHAR   (nombre completo, NO traducir)
  pila            VARCHAR   (apodo, NO traducir)
  dorsal          INT
  descripcion     TEXT NULL  → SIEMPRE NULL (bio va en jugador_traduccion)
  valoracion      INT
  genero          ENUM('H','M','?')
  posicion        ENUM('POR','DEF','MED','DEL')
  pais            VARCHAR(64)   código ISO: JP, ES, FR...
  altura          SMALLINT UNSIGNED  (cm)
  estilo          ENUM('PICARO','PRECISO','POTENTE','VALIENTE','AGIL')
  foto            VARCHAR NULL

--- jugador_traduccion ---
  id_jugador      INT FK → jugadores.id
  locale          VARCHAR(5)
  descripcion     TEXT   (bio ES / bio EN traducida)
  PK (id_jugador, locale)

--- supertecnicas --- (catálogo global, reutilizable entre jugadores)
  id              BIGINT AUTO_INCREMENT PK
  nombre          VARCHAR(128)   clave interna snake_case, SIN acentos
  potencia        TINYINT UNSIGNED
  tipo            ENUM('REGATE','DEFENSA','PARADA','TIRO')
  estilo          ENUM('PICARO','PRECISO','POTENTE','VALIENTE','AGIL')
  UNIQUE (nombre, potencia, tipo, estilo)

--- supertecnica_traduccion ---
  id_supertecnica BIGINT FK → supertecnicas.id
  locale          VARCHAR(5)
  nombre          VARCHAR(128)   nombre visible traducible
  PK (id_supertecnica, locale)

--- jugador_supertecnica --- (4 filas por jugador, orden 1-4)
  id              BIGINT AUTO_INCREMENT PK
  id_jugador      INT FK → jugadores.id
  id_supertecnica BIGINT FK → supertecnicas.id
  orden           TINYINT UNSIGNED  (1, 2, 3 o 4)
  UNIQUE (id_jugador, orden)
  UNIQUE (id_jugador, id_supertecnica)
